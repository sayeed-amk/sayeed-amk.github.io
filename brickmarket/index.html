Brick Market

A marketplace where kids can list their used Lego sets and sell them to friends. I designed and built it end to end in Laravel for Web Application Development (3004ICT): database, authentication, business rules, checkout and automated tests.

Why I built it

I started from one sentence and made every feature earn its place against it:

“This app helps my son list and sell his used Lego sets to his friends.”

That kept the scope honest. Swapping, online payments and stock quantities were left out on purpose and written up as future work. Because each listing is one physical set, a listing is simply available or sold, which removes the whole stock-counting problem.

What it does

  • Accounts and login with Laravel Breeze; the user's name is shown on every page
  • Full CRUD on listings, with server-side validation on every field
  • Ownership rules enforced on the server: editing someone else's set returns 403, even with a crafted URL
  • Photo upload (JPG/PNG/WEBP up to 2 MB), with old files cleaned up on replace or delete
  • Search, theme filter and pagination on the browse page
  • Session cart and checkout that turns the cart into an order
  • Private order history: only the buyer can open their own orders
  • Admin role via custom middleware, to manage the theme list
  • Sold sets are locked and can't be edited or deleted
  • Responsive layout with Tailwind CSS, from phone to desktop

Engineering decisions I can defend

Price is copied at checkout

The order lines live in an order_listing pivot table that stores price_at_purchase. If a seller changes a price later, it can't rewrite what someone actually paid.

Checkout is all or nothing

Checkout runs inside a database transaction. It re-reads each set, skips anything already sold or owned by the buyer, writes the order and marks the sets sold. If anything fails, no half-made order is left behind.

Security on the server, not the button

Hiding an Edit button isn't security. Every update and delete checks ownership first and returns 403. Admin pages sit behind a custom EnsureUserIsAdmin middleware.

Mass-assignment protection

New listings are created through the user relationship, and user_id and status aren't fillable, so a tampered form can't change who owns a set or mark it sold.

PHPUnit feature tests cover authentication, listing CRUD and validation, ownership (403 for non-owners), photo upload, cart and checkout including price-at-purchase, order privacy, and admin-only access. Some tests deliberately try to attack the app, for example signing up with is_admin in the form, or taking over someone else's listing through mass assignment.
